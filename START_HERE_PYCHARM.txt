RESILIENTCITY AI V4 EXPERIMENTAL — PYCHARM LOCAL EXECUTION

This branch preserves V3 as the controlled baseline and extends the learning lab with uncertainty-aware, adversarial evaluation.

1. Open PyCharm.
2. File > Open and select this repository.
3. Configure a Python interpreter (Python 3.12 recommended).
4. Open the PyCharm Terminal.
5. Run:
   python -m pip install -r requirements.txt
6. Run tests:
   python -m pytest -q
7. Open gui.py and Run 'gui'.

V4 validation checklist:
[ ] GUI opens as V4 Experimental
[ ] Scenario selector loads 20 synthetic scenarios
[ ] Original controlled scenarios remain available
[ ] Missing evidence can return INSUFFICIENT_EVIDENCE
[ ] Contradictory evidence can return UNRESOLVED
[ ] Out-of-scope evidence can return OUT_OF_SCOPE
[ ] Overlapping/critical context can trigger Human Gate
[ ] Critic can PASS, REVISE, or ESCALATE
[ ] Safety can APPROVE, APPROVE_WITH_LIMITATIONS, HUMAN_REVIEW_REQUIRED, or BLOCK
[ ] Agent Trace and Shared State expose uncertainty handling
[ ] Pilot Evaluation populates the dashboard
[ ] Forced-classification rate is reported
[ ] Insufficient-evidence recognition is reported
[ ] Contradiction detection is reported
[ ] Evidence traceability and reproducibility are reported

Methodology:
"These controlled scenarios are being used to evaluate architecture behaviour, traceability, escalation and reproducibility."

"Workflow validation ≠ real-world readiness."

"A good outcome is not always a classification. When evidence is missing, contradictory, or outside the system's validated scope, recognising uncertainty and escalating to a human is itself a successful outcome."

Do NOT describe synthetic results as real-world accuracy.
The timing metric is workflow execution time, NOT human review time.
Any future operational pilot must begin in shadow mode, with people making every operational decision.
